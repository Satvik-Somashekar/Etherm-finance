# Open Finance Aggregator

Open Finance Aggregator — an Account Aggregator-backed view of fragmented Indian
financial data, with a RAG layer for natural-language questions over your own
records. See [PROJECT_CONTEXT.md](PROJECT_CONTEXT.md) for the full design intent.

The Maven reactor contains:

- `data-generator` — seeded synthetic data for five FI types (deposit, mutual funds, insurance, EPF, equities), shaped like ReBIT Account Aggregator FI fetch responses. Payloads are unencrypted and every person, account and policy is invented.
- `ingestion` (port 8081) — validates FI fetch responses and stores the raw accounts in memory. Loads generated data at startup.
- `normalization` (port 8082) — scaffold only
- `retrieval` (port 8083) — scaffold only
- `rag-service` (port 8084) — scaffold only

There is no live AA integration; all data is synthetic.

An API gateway is intentionally deferred until the services expose public APIs that need centralized routing.

## Build

Requires Java 21 and Maven 3.9+.

```bash
mvn clean install
```

## Run a service

Each service binds its own port, so all four can run at once — one terminal each.

| Module | Port |
| --- | --- |
| `ingestion` | 8081 |
| `normalization` | 8082 |
| `retrieval` | 8083 |
| `rag-service` | 8084 |

## Generate synthetic data

```bash
mvn -pl data-generator exec:java -Dexec.args="--users 5 --seed 42 --out $PWD/data/synthetic"
```

The same seed always produces the same data. The default window is 1 Oct 2025 to 30 Sep 2026; change it with `--from` and `--to`.

## Run the ingestion service

```bash
ETHERM_SEED_DIR=$PWD/data/synthetic java -jar ingestion/target/ingestion-0.0.1-SNAPSHOT.jar
curl http://localhost:8081/api/customers
curl "http://localhost:8081/api/customers/user001@etherm-aa/accounts?fiType=DEPOSIT"
```

`POST /api/fi/fetch-responses` accepts one fetch response and returns 422 with a list of problems if it is malformed.

Verify it is running:

```bash
curl http://localhost:8081/actuator/health
```

Expected response:

```json
{"status":"UP"}
```

## Frontend

`frontend/` is a Vite + React + TypeScript app implementing the four product
screens against the Etherm Lumina design system in
[docs/design/DESIGN.md](docs/design/DESIGN.md).

```bash
npm --prefix frontend install
npm --prefix frontend run dev
```

It runs on `http://localhost:5173`.

| Route | Screen | Notes |
| --- | --- | --- |
| `/` | Dashboard | Net worth, allocation by FI type, recent activity, grounded insights |
| `/accounts` | Linked Accounts | FIP cards with sync freshness and consent expiry |
| `/oracle` | AI Oracle | Chat over consented records, with metrics, charts and source citations |
| `/consent` | Consent & Security | Consent posture, active sessions, consent ledger |

### Data

Every figure the UI renders comes from `src/data/mock.ts`, typed against the AA
FI schema shapes in `src/types/fi.ts` — nothing is hardcoded into a component.
Balances, allocation shares and aggregate totals are computed from those records
at render time, mirroring the retrieve-then-compute strategy the RAG layer needs:
totals are summed in code, never generated by the model.

Replacing the mock module with calls to `retrieval` and `rag-service` is the
intended next step; the Oracle composer already has the stub in place where
`POST /query` will go.

### Notes

- Privacy Mode (on `/consent`) masks every monetary figure app-wide via
  `src/state/PrivacyContext.tsx`; new money values should render through
  `<Money />` so they inherit that behaviour.
- Icons are Material Symbols, loaded from Google Fonts in `index.html`.
